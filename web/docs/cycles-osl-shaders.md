# Original Cycles node shaders

The installed Wasm `oslc` compiler builds all 103 node shaders selected by
Blender's original `cycles_osl_shaders` CMake target. This includes the
Principled, hair, volume and procedural texture shaders. The check uses a
private source copy so generated bytecode stays outside the pinned checkout.

Native Blender independently compiles each source through `_cycles.osl_compile`.
Its original OSL query binding then compares shader names, types and metadata,
all 719 parameters, defaults, arrays, output flags and parameter metadata with
the Wasm compiler's output. All comparisons passed. The native `stdcycles.h`
prelude matches the pinned source exactly.

The [recorded results](cycles-osl-shaders.json) include every source and bytecode
hash, the installed compiler hashes and native query results. Reusing build
outputs requires matching compiler, standard headers, source and CMake-wrapper
hashes, plus matching cached bytecode hashes. Changing those inputs rebuilds
the bytecode through the original target.

```sh
python3 web/tools/native_cycles_osl_shaders.py --jobs 2 --blender /path/to/native/blender
```

This requires the installed OSL recipe and its Node launcher. The original
imported executable target points to `oslc.js`; application build integration
must select the launcher so the command runs through Node.

These checks compile shaders and verify their metadata. They do not execute
every node or enable Cycles OSL rendering in the browser application. The
[kernel ABI check](cycles-osl-abi.md) and
[owned runtime check](jit-data-addresses.md) qualify those separate components.
